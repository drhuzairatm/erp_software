# Role and permission matrix (defaults)

Generated by `npm run docs:permissions` from the database on 2026-11-01. Roles are configured **per company**; these are the defaults installed for each company and can be changed under *Roles & permissions* (except the locked MD role).

## Roles

| Role | Locked | Privileged | 2FA required |
|---|:-:|:-:|:-:|
| Managing Director | ✓ | ✓ | ✓ |
| CEO |  | ✓ | ✓ |
| Company Manager |  |  |  |
| Sales / Counsellor |  |  |  |
| Documentation Staff |  |  |  |
| Visa Coordinator |  |  |  |
| Finance Staff |  |  | ✓ |
| System Administrator |  | ✓ | ✓ |

- **Locked (MD):** always holds every permission (including future ones); cannot be changed or reassigned in the app — use `npm run admin:create`.
- **Privileged:** assigning this role also requires *Assign privileged roles* (`users.create_admin`).
- **No escalation:** a user can only grant permissions they hold, only assign roles whose permissions they all hold, never edit their own role or membership, and only reset/deactivate people whose access is within their own.

## Financial privacy

Financial **amounts** require `payments.read` (MD and Finance by default). The CEO has `payments.status`, which only returns counts through the database function `app.payment_status_counts`; ledger rows, balances, payment timeline events, finance reports and the audit log (which contains amounts) are refused by row-level security.
